# iobrx 0.3.0

Versioned Linux x86-64 / CPython 3.11 release. Install the wheel from this
release without Cargo or a C++ compiler; `--only-binary=:all:` also prevents
implicit compilation of dependencies. PyPI availability and mirror propagation
are separate from GitHub assets; check the actual index before using it.

Adds 19 workflow APIs from IOBRpy plus signature-score optimization, including
standalone `extract_hla_read` with dependency auto-installation off by default. Numerical
and external-tool behavior remain explicitly scoped by the validation suite.
IOBRpy supplies reference resources and the original-workflow comparison path.

Reliability improvements:

- QC and MultiQC failures propagate to `runall`; failed stages do not receive completion markers.
- Dry runs print the full plan without creating directories, markers or merged results.
- QC, Salmon and STAR verify input/reference/tool and output SHA-256 values before skipping work. STAR requires both BAM and GeneCounts.
- `runall` checks calculation products and completion records on resume; unrelated notes and figures are excluded. CIBERSORT uses the original file-based solver at this boundary.
- Tables require a successful producing step and a matching output hash before reuse. Failed partial writes and interrupted deconvolution merges are retried. Existing schema 2 state remains readable; pre-schema-2 directories require a new `outdir`.
- `IOBRX_DISABLE_RUST=1` also disables the Salmon native parser.
- Fresh NMF output directories retain feature rankings.

The Omicos harness adds 16 typed adapters (27 analysis identifiers total).
HLA/SpecHLA and custom-reference BayesPrism remain direct Python capabilities.
Existing typing wrappers retain upstream environment installation behavior;
the new `extract_hla_read` defaults to `auto_install=False`.

Tutorials now include 28 executed notebooks: 23 matrix/file examples plus five
real FASTQ, Salmon, STAR/BAM, HLA extraction and SpecHLA examples, each with
two figure revisions. Synthetic and shortened-chain demonstrations remain
labelled. The new public-read comparison runs each arm three times with the
same tools and references, and archives all timings and product checks.

FASTQ, STAR BAM/counts, extracted HLA reads and 16-allele typing outputs match
on these fixtures. Salmon quantification varies across repeated original runs
as well as across wrappers. HLA extraction is slower for iobrx in this small
test; external-tool speed is not a blanket acceleration claim. See the
[complete recipe and observations](https://github.com/LCGaoZzz/iobrx/blob/v0.3.0/benchmarks/real_tools/README.md).
The NA06985 fixture is already HLA-enriched, and no independent genotype truth
panel is provided. These are workflow comparisons, not clinical validation.

Packaging targets Linux x86-64 CPython 3.11 with the tested numerical stack.
The release workflow builds and tests wheels and a container, chooses release
notes from the tag, and publishes only from an authorized version tag.
GitHub delivery is independent of the PyPI job, so a PyPI account/service
failure can be retried without rebuilding or overwriting the tested container.
`container-digest.txt` identifies the exact core-analysis image; external HLA
and alignment tools require the dedicated environment documented in the recipe.

The additional `iobrx-0.3.0-real-tools-evidence.tar.gz` attachment preserves the
compared products and compact logs, with a separate SHA-256 file. Its manifest
identifies raw files versus canonical FASTQ/JSON/SAM comparisons.
