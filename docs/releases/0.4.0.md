# iobrx 0.4.0

Packaging release: the reference data the kernels read is bundled inside the
wheel, and IOBRpy becomes an optional dependency.

- Reference data (LM22, EPIC TRef/BRef, quanTIseq, MCP-counter, ESTIMATE,
  BayesPrism inputs, TRUST4 references, annotation tables — 20 files, MIT
  provenance in `src/iobrx/_resources/NOTICE.md`) ships inside the wheel.
  `iobrx.resource_path(name)` resolves bundled data first, then an installed
  IOBRpy.
- IOBRpy moves to the optional `python` extra (Python fallback backend,
  quanTIseq and signature scoring, parity tests). The default install no
  longer pulls IOBRpy's transitive dependencies or their exact pins, and
  `import iobrx` no longer imports IOBRpy. Paths that reuse upstream helpers
  fail with an actionable `pip install 'iobrx[python]'` message.
- Dependency pins relax to ranges for coexistence with shared environments
  (e.g. the Omicos kernel); the validated exact numerical versions are
  published as the `strict` extra and remain what the official parity gates
  and CI assert. The `test` extra includes IOBRpy because the gates compare
  against the original.
- Fix the merge_salmon tqdm fallback shim for keyword-only calls (previously
  masked because IOBRpy always installed tqdm).
- Tests run green without IOBRpy: parity modules skip with an explicit
  reason; the smoke suite reads bundled resources.
- Document the extras, large-cohort thread guidance and CIBERSORT's fixed
  per-call overhead in README (+ zh-CN).
- The agent harness companion (`agent-harness`) moves to 0.3.0 with `.h5ad`
  inputs, batch alignment, and reference resolution compatible with both the
  bundled and the IOBRpy-backed layout.

Measured (fresh py3.11 venv, aliyun index): cold install 0.3.0
1372 s / 100 packages / 2156 MB -> 0.4.0 default 495 s / 31 packages /
789 MB; the wheel is 26.3 MB and self-contained.

The exact numerical versions validated for bit-exact parity remain
`numpy==2.2.6`, `scipy==1.16.3`, `scikit-learn==1.7.2`, `gseapy==1.3.1`
(install `iobrx[strict]`); on newer numpy the native solvers may differ by
the last ulp.
